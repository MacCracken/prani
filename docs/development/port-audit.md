# prani — Rust → Cyrius Port Audit

Per-module parity ledger for the 2.0.0 port. The Rust oracle is frozen at tag
`2.0.3` and read with `git show` ([ADR-0004](../adr/0004-cite-the-oracle-by-tag.md));
every Cyrius module must match it function-for-function. Update the relevant row
whenever a module's status changes.

**Status:** ✅ ported & tested · 🟡 partial · ⬜ pending
**LOC** = Rust lines (incl. tests) at `2.0.3:rust-old/src/` — fixed, the oracle
is frozen. **Tests** = assertions in that module's `tests/<mod>.tcyr`, **measured at 2.2.1**
with `cyrius test tests/<mod>.tcyr`. They move, and they have moved a long way
since the port (2.0.4 closed the parity shortfalls, 2.0.5 added the range guards,
2.2.1 the second sweep). The cross-module suites (hardening, layers, logging, the
alloc suites, `prani.tcyr`) are not in the column. Current totals live in
[`state.md`](state.md).

## Conventions established (apply to every module)

Proven reference template: **`src/error.cyr`, `src/rng.cyr`, `src/dsp.cyr`**
(+ their `tests/*.tcyr`). Read those first. Cross-repo analogs: `../svara/src/*.cyr`
(prani's dep, same idioms), `../naad/src/*.cyr`, `../naad/docs/development/port-audit.md`.

- **Two float formats** ([ADR-0010](../adr/0010-two-float-formats.md), 2.3.0). The
  port was f64 everywhere through 2.2.1. Since 2.3.0 a *real* is the build's float:
  f64 by default, f32 under `-D PRANI_F32`. Write arithmetic over `src/real.cyr`'s
  primitives (`pr_add` … `pr_ge`, `pr_clamp`, `pr_sin`, `pr_from`, `pr_to`), never the
  `f64_*` builtins. Widen into svara/naad/hisab/bayan with `pr_to64`, and narrow back
  with `pr_of64`. The f64 build compiles `src/f64/`, generated by `scripts/gen-f64.sh`,
  so its code is 2.2.1's builtins. The bar is **accuracy** against the f64 build, not
  the Rust's f32 bits: the Rust defined what prani does, not its numbers.
- **Float literals**: integers via `pr_from(n)`; non-integers as a module-top pair,
  `#ifdef PRANI_F32` with the binary32 bits and `#else` with the binary64 bits, each
  from the decimal in its comment. Generate the f64 one with
  `python3 -c "import struct;print(hex(struct.unpack('<Q',struct.pack('<d',V))[0]))"`
  and the f32 one with `'<I'` / `'<f'`.
- **Math API**: the primitives in `src/real.cyr`: `pr_add/sub/mul/div/neg/abs`,
  `pr_lt/le/gt/ge/eq` (write a compare as a bare truth value, `if (pr_lt(a, b))`),
  `pr_clamp/min/max`, `pr_sin/cos/sqrt/pow/cbrt/floor/trunc`, and constants
  `PR_ONE/PR_TWO/PR_HALF/PR_PI/PR_TAU`. An oscillator's time and phase use the f32-only
  `pr_time` / `pr_sinw` in an `#ifdef PRANI_F32` arm.
- **`enum` → integer `var` constants** (see error.cyr / any svara enum port).
- **`enum` errors → integer codes**: fallible fns return `PRANI_ERR_NONE` (0) or a
  negative `PRANI_ERR_*` from `src/error.cyr`. `Option<Error>` → the code directly.
  svara errors map via `prani_from_svara(svara_code)`.
- **`Result<T>` / `Option<T>`** → sentinel returns (error code, or a NaN/-1 sentinel)
  unless a real payload is needed (then `lib/tagged.cyr`).
- **`Vec<T>` → stdlib `vec`**, created and grown through prani's funnel:
  `prani_vec_new` / `prani_vec_push` (each returns a negative `PRANI_ERR_ALLOC` on a
  refusal), read with `vec_len`/`vec_get`/`vec_set`. f64 elements store directly in
  the 8-byte slots. `&mut [f32]` / `&[f32]` buffers → a `vec` handle (mutated in
  place / read). A raw `vec_new` / `vec_push` fails CI since 2.2.0
  (`scripts/check-alloc.sh`, ADR-0008).
- **structs** via `#derive(accessors)` + `prani_alloc(sizeof(T))`, checked with
  `if (p < 0) { return p; }` (a raw `alloc` is banned the same way); methods become free
  functions `TypeName_verb(self, …)`; accessors are `TypeName_field(self)` /
  `TypeName_set_field(self, v)`. Fixed `[f32; N]` inline arrays → a `vec`.
- **Every top-level symbol is `prani_`/`PRANI_`/`Pr`-prefixed** — the bundle is one
  flat namespace shared with svara (`svara_*`) and naad (`validate_*`, `ERR_NONE`,
  `flush_denormal`). Front-load collision avoidance. `#derive(accessors)`
  auto-prefixes field accessors by struct name (pick distinct struct names).
- **`&mut u32/u64` PRNG state** → the `PrRng` struct (`src/rng.cyr`); u64 wrap is
  plain `*`/`+` on i64; `>>` is logical; u32 truncate with `& 0xFFFFFFFF`.
- **Module files do NOT `include` each other** — the build/test entry includes them
  in dependency order. The stdlib and the deps resolve from `cyrius.cyml`; `src/main.cyr`
  and most units that reach svara also include the dep bundles explicitly
  (`lib/hisab.cyr`, `lib/goonj.cyr`, `lib/naad.cyr`, `lib/svara.cyr`, in that order),
  which fixes their order ahead of prani's modules.
- **serde RESTORED** (2.0.1) via `#derive(Serialize)` + `bayan`: every type that
  had `#[derive(Serialize, Deserialize)]` gets a `*_to_json` / `*_from_json_str`
  codec + a roundtrip test. Real fields are typed `i64` so they serialize as exact
  bit patterns, and a document holds f64 bit patterns in both builds (ADR-0010). Display-string
  tests dropped (no Display in Cyrius). Logging RESTORED via sakshi (`src/logging.cyr`).
  All other `#[test]` blocks ported one-for-one. Where a Rust
  module had NO `#[test]` block (its behaviour lives in `tests/integration.rs`),
  write focused behavioural tests that lock parity (golden values from the oracle).
- **`math.rs`** (thin f32 sin/cos/exp/sqrt/powf wrappers) is folded into the
  `pr_*` primitives — **no `math.cyr` module** (same as svara/naad). In the f32 build
  they compute in f64 and round once (ADR-0010).
- **Cross-check every module against the oracle** (`git show
  2.0.3:rust-old/src/<mod>.rs`) — correctness bar is "matches what Rust did".
  Diverge only with a documented parity note.

## Test harness pattern

Each module gets `tests/<mod>.tcyr`:
```
include "src/error.cyr"        # deps first, in dependency order
include "src/logging.cyr"      # any module that calls prani_log_* needs this
include "src/<mod>.cyr"
alloc_init();
test_group("group name");
assert_eq(actual, expected, "message");   # also assert_neq/streq/lt/gt/gte/lte
var rc = assert_summary();
syscall(60, rc);
```
Run: `flock <scratch>/prani-build.lock cyrius test tests/<mod>.tcyr`. Assert on f64
**bit patterns** for exact values, or use `f64_lt(f64_abs(f64_sub(a,b)), tol)` for
tolerance. stdlib (assert/vec/math/alloc) auto-resolves — do not include it.

## Toolchain & commands

- cycc pin: **6.7.18** (`cyrius.cyml [package].cyrius`).
- Deps: svara/naad/hisab/goonj as `dist/*.cyr` git+tag bundles, vendored in `lib/`;
  sakshi and bayan are stdlib leaves (`[deps].stdlib`, since 2.1.2). Do not modify
  `lib/`.
- **Concurrency**: `cyrius test`/`build`/`deps` re-resolve deps and race on
  `cyrius.lock`. Parallel porting agents MUST serialize every `cyrius …` call
  behind a shared file lock: `flock <scratch>/prani-build.lock cyrius …`.

**The ledger above did not stop at 2.0.3.** 2.0.4 → 2.0.11 carried the suites
from 770 to **1,946 assertions across 18 suites** and retired `rust-old/`
(2.0.8) — that history is in [`CHANGELOG.md`](../../CHANGELOG.md) and the current
figures in [`state.md`](state.md); this file tracks per-module parity, not
releases.

**A third defect category the parity bar cannot see.** 2.0.3's CRITICAL was
neither an inherited oracle defect nor a transcription error: svara 3.x replaced
an infallible constructor with a checkable error code, and the port went on using
the return value as a pointer. Parity against the oracle cannot catch this,
because the oracle has no such failure to compare against, and a symbol-level
dependency review cannot either, because the name and arity did not change — only
the MEANING of the return. When bumping a dependency, ask what each consumed
return value now means, not just what it is called.

### Parity method

svara-independent math (error codes, RNG golden values, contour interpolation,
effective_f0, builder clamps, bridge conversions, species params + all 13
`resonance_seed`s, spatial DSP, intent/fatigue/emotion tables) is asserted at
**exact f64 bit patterns**. Full synthesis paths (which route through svara's
own DSP, where f32→f64 widening diverges bit-for-bit) are asserted
**structurally**: non-error return, exact buffer length, all-finite samples, and
bit-identical determinism across identical runs — and, **since 2.0.4, by
magnitude** as well: peak / energy against the oracle's own bars. The structural
bar alone was not enough, and 2.0.4 proved it: an all-zero buffer satisfied every
synthesis assertion in the project. Since 2.2.1 `tests/layers.tcyr` pins 15 render
levels to a relative 1e-9 of their recorded values.

Since 2.3.0 every suite runs in both formats
([ADR-0010](../adr/0010-two-float-formats.md)). The f64 build holds every assertion
bit for bit. The f32 build holds the same expected values, stated as the f64 values
they should be, to the measured accuracy of each computation (`assert_real`, in
`tests/realt.cyr`): render levels within a relative 1e-6, and single computations
within one or two f32 ulps. Bit parity with the Rust's f32 is not the bar.
