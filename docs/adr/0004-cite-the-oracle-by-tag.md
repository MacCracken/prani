# 0004 — Cite the Rust oracle by tag, never by working-tree path

**Status**: Accepted
**Date**: 2026-08-31

## Context

`rust-old/` is the frozen Rust parity oracle. Roadmap **2.0.8** retires it: once
the port's own suites carry the parity guarantee, the directory is 4,646 lines of
source that nothing builds, tests, or bundles.

Removing it breaks every reference to it. The tree carries **83** `rust-old`
citations across **42** maintained files — source headers (`# Ports
rust-old/src/voice.rs`), test headers (`# rust-old/src/rng.rs had no #[test]
blocks`), every doc, and two line-level citations that are the sharpest case:

```
src/stream.cyr:240    # (rust-old/src/stream.rs:184) wraps only the COPY in `if let Ok(block)`
src/tract.cyr:104     # `rust-old/src/tract.rs:CreatureTract::new` returns `Self`, because …
```

A bare path plus a line number is unresolvable the day the directory goes. The
reader cannot even tell whether the citation was ever right.

Two facts make a tag-based rule work, both verified 2026-08-31:

- **Every tag is a commit reachable from `main`**, so `git show <tag>:<path>`
  resolves without a checkout, a stash, or a detached HEAD.
- **The oracle's path changed at 2.0.0.** The port *created* `rust-old/` by
  moving the Rust aside, so the same file lives at two paths depending on era:

  | Era | Tags | Oracle path |
  |---|---|---|
  | Port | `2.0.0`, `2.0.1`, `2.0.2`, `2.0.3`, … | `rust-old/src/voice.rs` |
  | Rust | `1.0.0`, `1.1.0` | `src/voice.rs` |

  A rule that names only one of these is wrong half the time.

A separate measurement correction belongs here, because the wrong number was
about to become a release gate. The roadmap recorded **176 citations across 45
files**. That count included `lib/` — the *vendored* stdlib and dependency
bundles, which carry **143** `rust-old` citations belonging to naad, goonj,
svara and hisab, and which CLAUDE.md forbids modifying — and it under-counted by
exactly the 56 in `lib/naad.cyr`. The number prani can actually act on is the
one above: **83 across 42 files**, reproducible with

```sh
git grep -c 'rust-old' -- . ':!lib/' ':!dist/'
```

`dist/prani.cyr` is excluded because it is regenerated by `cyrius distlib`, not
edited; its 17 citations follow whatever `src/` says.

> **Note, 2.0.8 (2026-08-31) — this section's own correction needed correcting.**
> When the sweep ran, the real figure was **297 citations across 53 files**, not
> 83 across 42: 2.0.4–2.0.7 added heavily-citing docs and the gate number was
> never re-measured. Worse, `git grep 'rust-old'` is itself the **wrong search** —
> **77** citations name an oracle file with no `rust-old/` prefix at all
> (`voice.rs:227-231`), so they were invisible to it; the line-numbered ones were
> converted, and a further **33** that were tag-qualified but not paste-able
> (`rust-old/…:904-915 @ 2.0.3`, `2.0.3: rust-old/…`) were normalised. See
> CHANGELOG 2.0.8. The **rule** below is unaffected — it is what the sweep
> applied. The **Precondition** below is still open: `git push --tags` is recorded
> as an outstanding follow-up on 2.0.8, and `git ls-remote` still cannot be
> reached from this environment.

## Decision

**A citation to the Rust oracle names a tag. `git show` is how you read it.**

```sh
git show 2.0.3:rust-old/src/voice.rs          # port era  — the oracle at rust-old/
git show 1.1.0:src/voice.rs                   # Rust era  — the Rust WAS src/
git show 2.0.3:rust-old/tests/integration.rs  # 72 of the 73 #[test] blocks
git show 2.0.3:rust-old/src/lib.rs            # …and the 73rd
```

Concretely:

- **In prose and comments, write `2.0.3:rust-old/src/tract.rs:104`**, not
  `rust-old/src/tract.rs:104`. The tag is part of the citation, the same way a
  commit hash is part of a blame reference.
- **`2.0.3` is the canonical oracle tag** — the last release before the arc that
  removes the directory, and the state every parity claim in the tree was checked
  against. Cite an earlier tag only when the point *is* the earlier state.
- **Line numbers are only valid with a tag.** A bare line number is a citation
  with no referent and should be treated as a defect in review.
- **Scope**: `src/`, `tests/`, `docs/`, and the root markdown. Not `lib/` (vendored
  — not ours to edit, and its citations point at *other* projects' oracles) and
  not `dist/` (regenerated).
- The sweep that converts the existing 83 is roadmap **2.0.8**'s gate item. This
  ADR is the rule it applies; it is in force for anything written from now on.

**Precondition**: the rule assumes the tags exist wherever the reader is. All six
are local commits today; `git ls-remote` could not be checked from this
environment. **Push tags to `origin` before 2.0.8 removes the directory** — an
unpushed tag is a citation that resolves only on one machine.

## Consequences

- **Positive** — the oracle stays readable forever without the working tree
  carrying it. Every citation becomes self-verifying: paste it into `git show`
  and either the file appears or the citation was wrong.
- **Positive** — it removes the reason to keep `rust-old/` "just in case", which
  is the failure mode that leaves a dead directory in a repo for years.
- **Negative** — reading the oracle is now one command instead of opening a file,
  and editors will not follow the reference. Grep-across-the-oracle becomes
  `git grep <pattern> 2.0.3 -- rust-old/`, which is a thing contributors must
  learn.
- **Negative** — prani now depends on its own git history in a way it did not
  before. A shallow clone (`--depth 1`) or a squashed history import loses the
  oracle entirely. `git fetch --tags --unshallow` is the escape hatch, and it
  belongs in the contributor doc.
- **Neutral** — the era split is a permanent wart. It cannot be fixed without
  rewriting history, and it is cheaper to write the rule down twice than to
  rewrite six tags.

## Alternatives considered

- **Keep `rust-old/` forever.** Rejected: it is the status quo, and the cost is
  permanent — 4,646 lines that every audit, every `git grep`, and every new
  contributor must be told to ignore, plus a `Cargo.toml` that invites a
  `cargo build` that has nothing to do with the project.
- **Copy the oracle into `docs/` as a frozen appendix.** Rejected: it is the same
  4,646 lines in a directory where they are harder to justify, and a copy of a
  copy drifts. Git already stores exactly one immutable version of it.
- **Convert every citation to a permanent commit hash** (`62bcd88:rust-old/…`).
  Rejected: hashes survive re-tagging, which is the only advantage, and they are
  unreadable in a comment. Tags are reachable from `main` and this project does
  not move them; if that ever changes, this ADR is superseded, not patched.
- **A git submodule pinning the Rust at a separate repo.** Rejected: it exports a
  clone-time dependency to every consumer to solve a problem only maintainers
  have, and submodules fail closed (an empty directory) rather than loudly.
- **`git archive` a tarball into releases.** Rejected: it is `git show` with extra
  steps and a second thing to keep published — and the roadmap already records
  that depending on someone else keeping something published (the oracle's
  crates.io dependencies) is a risk, not a plan.
