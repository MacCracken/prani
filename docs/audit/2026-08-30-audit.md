# prani — P(-1) sweep, 2026-08-30 (v2.0.2 tree → repaired in 2.0.3)

Scaffold-hardening + security sweep of the whole 4,139-line Cyrius tree (as of
the 2.0.2 tag; 2.0.3 is 4,362 lines), run
against the 2.0.2 tree (cyrius 6.5.36, svara 3.5.3 / naad 2.2.2 / hisab 2.11.2 /
goonj 2.0.4 / sakshi 2.4.12). This closes the one unmet 2.0.0 criterion on the
roadmap — *"Security audit pass (`docs/audit/YYYY-MM-DD-audit.md`) — deferred to
a work-loop cycle"*.

**11 findings: 8 repaired in 2.0.3, 3 accepted and documented.** Every repair has
a regression group in [`tests/hardening.tcyr`](../../tests/hardening.tcyr)
(53 assertions) written so it fails on the 2.0.2 tree. Three divergences from the
oracle are recorded as [ADR-0001](../adr/0001-check-svara-tract-constructor.md),
[0002](../adr/0002-deserializers-report-parse-failure.md) and
[0003](../adr/0003-failed-fill-reports-zero-and-retires.md).

## Method

Six dimensions over every module, plus the two the user asked for on top of the
standard sweep (refactor, optimization):

1. **Memory safety** — every `alloc(N)` / `var buf[N]` / `vec_get` index / raw
   pointer use, and every value used as a pointer that could be an error code.
2. **Input validation** — every public entry point, against 0, negative, NaN,
   ±inf, absurdly large, and malformed-serialized input.
3. **Guard/threshold class** — the defect shape hisab has now recorded thirty-odd
   times: *a guard comparing a quantity against a threshold that is wrong for it,
   then fabricating a plausible answer.* Extended here to its sibling: *a
   fallible call whose failure is never checked.*
4. **Arithmetic** — every `f64_div` denominator, every `f64_to` conversion
   feeding a loop bound or allocation size, every integer product that can
   overflow.
5. **Oracle parity** — for each finding, whether the Rust oracle has it too
   (inherited) or the port introduced it.
6. **Docs / lint / dead contracts** — comments asserting invariants the code
   does not hold.

Primitive semantics were **measured, not assumed**, before any finding was
believed:

| Probe | Result |
|---|---|
| `f64_clamp(NaN, 0, 1)` | returns **NaN** — both comparisons are false, so NaN passes straight through every clamp in the tree |
| `f64_max(NaN, 5)` / `f64_max(5, NaN)` | **5** / **NaN** — order-dependent |
| `f64_to(NaN)`, `f64_to(inf)`, `f64_to(1e19)` | all **i64::MIN** (saturating) |
| `bayan_json_v_obj_get(0, k)`, `bayan_json_v_int(0)` | both **0** — null-safe by design |
| `vec_get` out of range | writes to stderr and **aborts** (fail-fast, not silent) |
| `vec_push` on allocation failure | returns **-1**, never checked by prani |
| `svara_tract_new` at 0/1/10/49/50/100/999/1000 | **-1** at every one; a pointer at 4000 and above |

⚠ **The probe was wrong before the code was.** The first three bisect runs
reported a hang, and the finding was very nearly filed as an infinite loop. Two
instrument defects produced that: `${PIPESTATUS[0]}` is a bashism that expands to
nothing under this project's zsh, so every "exit=124 / timed out" reading was
fabricated by the harness rather than measured; and the probes printed through
`print`, which was silently producing nothing in that unit, so the bisect markers
that would have located the fault never appeared. With `$?` captured directly and
markers written through `test_group`'s raw syscall, the same input reported
**exit 139 — SIGSEGV**, and the real defect (F1) was three frames further up than
the one being chased. *Check the probe before believing the probe.*

## Findings

| F2 | LOW | `voice.cyr:vocalize_with_intent` | `block_size` is 0 below 50 Hz; the loop advances by it | inherited (`2.0.3:rust-old/src/voice.rs:227`) | **repaired** (defense in depth) |

### F1 — the one that mattered

The oracle's `VocalTract::new` returned `Self`; it could not fail. svara 3.x
hardened it into a checkable code that rejects every sample rate ≤ 1000 Hz. The
port kept the oracle's shape and used the return as a pointer regardless, so

```
crvoice_vocalize(wolf, HOWL, /*sample_rate*/ 10.0, /*duration*/ 1.0)   ->  exit 139
```

reached `svara_tract_set_formants_from_target(-1, target)` and dereferenced `-1`.
Reachable from `crvoice_vocalize`, `crvoice_vocalize_with_intent`, the cat-purr
path, `stream_fill_buffer` and `crtract_from_json_str` — that is the entire
public synthesis surface.

This is neither an inherited oracle defect nor a transcription error. It is a
third thing worth naming: **a contract that changed underneath the port**. hisab
recorded the value-level version of this as *"a constant derived from a
dependency is a measurement, and it goes stale silently."* F1 is the same
sentence one level up — *a contract derived from a dependency is a measurement*.
The 2.0.2 dependency bump reviewed every symbol prani calls for **renames and
signature changes**, and found two; it did not ask whether any of them had
changed **what a return value means**, which is invisible to that check.

### Accepted, not repaired

- **F9 — unchecked allocation.** `alloc()` returns 0 on exhaustion and prani
  stores through it at 27 sites; `vec_push` returns -1 and no call site checks,
  so an exhausted arena silently truncates a buffer. Not repaired because the fix
  is not local: it would put an error return on every constructor in the library,
  which is a larger API decision than a repair release should make, and the
  failure it guards against (a bump arena that never frees actually running out)
  takes the process down anyway. **Filed as roadmap 2.1.0.** The measured
  allocation reductions in F7/F8 attack the same problem from the other end.
- **F10 — chorus length overflow.** Requires a `timing_spread` around 1e14
  seconds. Left as-is because the guard belongs with the general input-range
  validation deferred in ADR-0002 — roadmap 2.0.5 — not bolted on alone.
- **F11 — NaN propagation.** `f64_clamp` passes NaN through, so a NaN
  `sample_rate` or `velocity` reaches svara or produces an empty buffer rather
  than an error. Now bounded rather than open: F1's guard rejects a NaN sample
  rate outright (asserted in `hardening.tcyr`), and `f64_to(NaN)` saturating to
  i64::MIN means every affected loop bound is negative and the loop simply does
  not run. What remains is a silent empty result where an error would be better —
  the same range-validation decision deferred in ADR-0002 — roadmap 2.0.5.

## Refactor

Two loop shapes had reached **three verbatim call sites each**, which is the bar
CLAUDE.md sets ("wait for the third instance before extracting an abstraction"):

- `prani_vec_extend(dst, src)` — was open-coded in `sequence_call_bout_synthesize`,
  `sequence_call_phrase_synthesize`, and `crvoice_vocalize_with_intent`.
- `prani_vec_push_zeros(v, n)` — was open-coded in the bout gap, the phrase gap,
  the chorus mix initialisation, and `stream_next_block`.

Both live in `dsp.cyr` and are behaviour-preserving. `prani_vec_push_zeros`
additionally makes one shared edge explicit rather than incidental: every call
site derives `n` from `f64_to(seconds * rate)`, which saturates to i64::MIN on
NaN, and a non-positive count must append nothing.

`species_params` was split into a table (`species_params_into`, writing into a
caller-owned struct) and an allocating wrapper, so the 13-species table has
exactly one copy while both an allocating and a non-allocating entry point exist.
That is what makes F7's repair possible without duplicating the table.

**Two duplications were found and deliberately left alone**, both at two
instances rather than three: `crtract_synthesize_stridulatory`'s bee branch is
byte-identical to `crtract_synthesize_vibratile`, and the `boundary_boost` block
is duplicated verbatim between `voice.cyr` and `stream.cyr`. Held as a roadmap
watch item until the third instance.

## Optimization

The benchmarks did **not** move: 19 ns/sample dcblocker, 14 ns/sample rng,
69 ns/frame emotion, 211 µs for the 0.05 s wolf howl — all within noise of 2.0.2.
No speed claim is made. The win is **allocation**, on a library whose allocator
is a bump arena that never frees, and it is measured with `alloc_used()` rather
than calculated:

| Path | Before | After | Measured by |
|---|---|---|---|
| `prani_ffi_voice_set_size` (an RTPC a host may call per frame, per creature) | **168 B retained per call** | **0 B** | both ends measured with `alloc_used()` over 1000 calls: 168,000 B before (`sizeof(CreatureVoice)` 40 + `sizeof(SpeciesParams)` 128), exactly 0 after |
| `voice.cyr` block loop | one `SynthesisOptions` per 20 ms of audio (50/s) | one per call | same group |

The FFI figure is the one that mattered: at 60 fps across 100 creatures that was
about 1 MB/second retained for the life of the process. svara's own
`streaming.cyr` states the rule this violates — *"an allocation inside an audio
callback is not a leak that grows slowly, it is one that ends the process."*

⚠ The first attempt at the FFI repair **measured 128 B/call still retained** and
the assertion failed. `crvoice_reset_individual` had been written to call
`species_params()`, which allocates. Only the table split above got it to 0. The
assertion was written before the repair was believed, which is why the shortfall
was caught rather than shipped as "no longer allocates".

## What was clean

Recorded so a later sweep knows it was checked, not skipped.

- **`vec_get` is bounds-checked** by the stdlib and aborts loudly, so the
  three-slot `vec_get(target, 0..2)` reads in `crtract_set_formant_blend` cannot
  corrupt memory on a short vec.
- **Every contour interpolation guards its divisor** —
  `if (f64_ge(f64_abs(f64_sub(t1, t0)), PRANI_EPSILON) == 1)` in both
  `crvoice_pitch_contour_f0_at` and `stream_pitch_contour_at`. This is the guard
  class that has failed thirty times in hisab; here it is correct in both copies.
- **`sequence_synthesize_chorus`'s modulo divisor is floored before use**
  (`if (mo < 1) { mo = 1; }`), so the `% divisor` cannot divide by zero.
- **`spatial_apply_doppler_shift`'s output length is bounded** — the velocity
  clamp puts `ratio` in [0.526, 10], so `out_len` cannot exceed 1.9 × input.
- **No syscalls, no command execution, no path handling, no network input.**
  prani's only external input surfaces are numeric parameters and JSON, both
  covered above. The `sys_system` / `exec_cmd` / path-traversal items on the
  standard checklist are not applicable.
- **`prani_ffi_*` null-checks every handle** before use, on all seven entry
  points.
