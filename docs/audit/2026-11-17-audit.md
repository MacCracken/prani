# prani — P(-1) sweep, 2026-11-17 (v2.2.0 tree → repaired in 2.2.1)

Second whole-tree sweep: audit, refactor, hardening and optimization, run against the
2.2.0 tag (6,583 lines of `src/`, 19 suites / 2,287 assertions; cyrius 6.7.18, svara
3.14.0, naad 2.3.5, hisab 3.5.0, goonj 2.3.2, sakshi 2.5.10). The first sweep
([2026-08-30](2026-08-30-audit.md)) ran on 2.0.2. Since then the tree has had input-range
validation (2.0.5), the svara 3.x excitation recalibration (2.1.2, ADR-0007) and the
allocation-failure contract (2.2.0, ADR-0008).

## Summary

Four reviews confirmed **53 findings**: 6 HIGH, 18 MEDIUM and 29 LOW. Verifying them
turned up four more. **2.2.1 repairs 52 of the 57.** Each repair carries a
regression test, and each test was run against 2.2.0 and fails there. The
dead-handle group in `tests/hardening.tcyr` cannot run on 2.2.0 at all: 2.2.0
faults on its first assertion.

- **Faults.** 2.2.0 had SIGSEGVs reachable through public functions in two ways. A
  function read a null or error handle it was given (A6, B9, C1, C2), or a null
  name or message reached `strlen` (A3, V3). Every public function that takes a
  handle now answers one without reading it.
- **Silent wrong output.** This is the larger class:
  - a document missing a field decoded as a Wolf (A2, C4, C5, B5);
  - a raw-set effort of 2.0 rendered as success (A1);
  - a stream's level depended on the host's buffer size, by 6–20 dB (B3);
  - a MATING chorus cut every call in half (C3);
  - a wolf whose params said vibratile rendered a buzz as a howl (V1).

  Six such defects were faithful to the oracle, and
  [ADR-0009](../adr/0009-renders-do-not-depend-on-how-they-are-cut.md) repairs them.
- **Gates that could not fail:**
  - `check-alloc` passed `alloc (n)` (D4);
  - no test pinned the level of any render past the tract (D2);
  - the O2 budget bounded a 16-byte struct by 1,000,000 bytes (D3);
  - the fuzz harness ignored its input (D17);
  - the bench baseline was two toolchains old (D5).

  Each gate now fails on what it claims. The proofs are below.
- **Kept or deferred, with reasons:**
  - A7 is blocked upstream (⛔ stdlib `vec_with_capacity`);
  - B13 is kept as API, and now tested;
  - C10 and V4 are decisions, on the roadmap for 2.3.x;
  - C13 has two of its four sub-items repaired.

The audio changes are measured in ADR-0009. In short, at 44.1 kHz nine of the 13
species render bit-identical to 2.2.0. No render anywhere changed its status or
length, and none became non-finite.

## Method

Four independent reviews, each in its own copy of the 2.2.0 tree, so no probe could
touch the repository or race on `cyrius.lock`:

| Review | Scope |
|---|---|
| A | `voice.cyr`, `preset.cyr`, `ffi.cyr` |
| B | `tract.cyr`, `stream.cyr`, `dsp.cyr` |
| C | `species`, `sequence`, `emotion`, `fatigue`, `spatial`, `bridge`, `vocalization`, `rng`, `error`, `logging`, `main` |
| D | the tests, the gate scripts, CI, the examples and the maintained docs |

Each review covered the first sweep's six dimensions: memory safety, input validation,
the guard/threshold class, arithmetic, oracle parity, and dead contracts. Each also
covered refactor (duplication at three instances, dead code) and optimization (work and
allocation on per-sample, per-block and per-call paths). D's dimension was whether the
gates can catch what they claim: vacuous assertions, shown with mutants, and scripts
that can be evaded, shown with planted lines.

**Nothing was accepted on a reviewer's word.** Every finding below was reproduced
again on the 2.2.0 tree before it was repaired, and each repair's regression test was
run against 2.2.0 to show that it fails there.

Primitive semantics were re-measured on cyrius 6.7.18, not carried over from the first
sweep:

| Probe | Result |
|---|---|
| `f64_clamp(NaN, 0, 1)` / `f64_clamp(+inf, 0, 1)` | NaN / 1.0: NaN passes every clamp, while an infinity is bounded |
| `f64_max(NaN, 5)` / `f64_max(5, NaN)` / `f64_min(NaN, 5)` | 5 / **NaN** / 5: order-dependent |
| `f64_to(NaN)`, `(+inf)`, `(-inf)`, `(1e19)`, `(-2.7)` | 0, INT64_MAX, INT64_MIN, INT64_MAX, −2: saturating, truncating toward zero |
| `f64_div(1, 0)` / `f64_div(0, 0)` | +inf / a NaN **with the sign bit set**, so its i64 bits are negative and `prani_is_err` reads it as an error code |
| `VEC_CAP_MAX` | 2^28; a push past it ends the process in the stdlib |

## Findings

Origin **oracle** means the defect is in `2.0.3:rust-old/` too, so its repair is
a divergence. Each such repair is covered by an ADR:

- ADR-0009 for B1–B4, B10 and C3;
- ADR-0006 and 2.0.5's range rules (input the oracle accepted, refused) for C6 and C9;
- ADR-0002 (a decoder reports what it cannot build faithfully) for V1.

## Proving the gates

Each gate repair was shown to fail on what it claims:

| Gate | Proof |
|---|---|
| `check-alloc.sh` (D4) | Six plants, each of which fails the gate. Five go in a scratch copy of `src/spatial.cyr`: `alloc (n)`; `vec_new` with its `()` on the next line; `vec_push (v, n)`; the same split around a blank line; and `&alloc`. The sixth is `alloc (size)` in `src/error.cyr`. The control, `prani_alloc(8)` with `alloc(8)` in a comment, passes, as does the tree. A plant in `src/sub/x.cyr` also fails it. |
| `run-examples.sh` (D11, D15) | Three plants fail it: a directory with only `basic.cyr` fails on the four missing examples, 2.2.0's `error_handling.cyr` fails `cyrfmt`, and a 132-character comment fails lint. The tree passes. |
| `bench-check.sh` (D5, D12) | A harness with a syntax error prints its diagnostic and exits 1, and TMPDIR is left empty. `--write` records 18 rows with the host, toolchain and tree. A compare against the old baseline warns that it was recorded on another toolchain. |
| `tests/layers.tcyr` (D2) | It catches all 14 mutants of the render layers listed below, each one edit in `src/`. On 2.2.0 it fails at exactly the four renders ADR-0009 moves. |
| `tests/prani.fcyr` (D17) | On 2.2.0 it reports a violation at round 786: `preset_from_json_str` accepts a name containing `\`, and refuses its re-encoding (A3). On 2.2.1, 1,500 mutated inputs × 4 decoders pass. |
| Regression groups | Each 2.2.1 group was run against the 2.2.0 tree and fails there. The B2/B4/C3 group was extracted to run on its own, because the full hardening suite faults on 2.2.0 before reaching it. The C11 and D16 forms do not exist on 2.2.0, so their groups do not compile there. |

## Checked and clean

The reviews checked these and found them clean:

- **Tables against the oracle:**
  - all 13 species rows × 16 fields, and the 13 bout templates;
  - the 13 resonance seeds, recomputed from f32 bits;
  - `supports_vocalization`;
  - the intent and emotion tables and thresholds;
  - the fatigue formulas;
  - the pitch contours, formant keyframes, nasal fractions, spectral offsets,
    envelope fractions and AM pattern;
  - the 11 presets and their build order.
- **Constants and PCG32.** Every IEEE hex constant in voice.cyr and preset.cyr
  decodes to its comment, and PCG32 matches Python for 7 seeds.
- **Divisors and casts.** Every divisor in voice, tract and stream is guarded.
  Every `f64_to` that feeds a loop bound is ranged first. The stream's counters stay
  below 2^53.
- **Stack buffers.** `var row[128]` and `var vt[80]` equal their struct sizes, and
  tests pin both.
- **Extreme rates.** At sample rates of 1e6 up to f64::MAX, every apparatus and all
  13 species stay finite.
- **Toolchain.** `cyrius distlib` reproduces the bundle byte for byte, and
  `cyrius deps --verify` and `--locked` both pass.
- **Examples.** The FFI and Cyrius drains are sample-identical.
- **CI.** The installer pin extraction and the version check are correct.
